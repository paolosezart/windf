--------------------------------------------------------------------------------
  ЧАСТЬ 0. КРАТКО О ТОМ, ЧТО МЫ ДЕЛАЕМ
--------------------------------------------------------------------------------

  Мы устанавливаем Ollama — программу, которая запускает языковые модели
  прямо на вашем компьютере. Никаких интернетов, никаких лимитов, никакой
  оплаты. Модель работает локально, пока вы не выключите компьютер.

  Что понадобится:
    - около 10-20 ГБ свободного места на диске D
    - 15-20 минут времени
    - терпение на скачивание (интернет не быстрый, файлы весят гигабайты)

  Важное ограничение вашего железа:
    - Видеокарта: 4 ГБ, из них свободно ~3.3 ГБ (Windows забирает ~0.7 ГБ)
    - Значит, целиком на GPU влезают только модели размером до ~3 ГБ
    - Процессор i7-3770 старый (2012 год), это может дать сбой — см. ЧАСТЬ 4

  Правило проверки: после КАЖДОГО шага смотрим результат.
  Если что-то не так — останавливаемся и идём в ЧАСТЬ 9 (аварийные сценарии).


--------------------------------------------------------------------------------
  ЧАСТЬ 1. ВЫБОР ДИСКА ПОД МОДЕЛИ
--------------------------------------------------------------------------------

  1.1. Откройте PowerShell (Пуск -> наберите "PowerShell" -> Enter).

  1.2. Введите команду:

       Get-Volume | Where-Object {$_.DriveLetter} | Select-Object DriveLetter, FileSystemLabel, @{n='SizeGB';e={[math]::Round($_.Size/1GB,1)}}, @{n='FreeGB';e={[math]::Round($_.SizeRemaining/1GB,1)}}

  1.3. Резервная команда, если первая не сработала:

       Get-CimInstance Win32_LogicalDisk -Filter "DriveType=3" | Select-Object DeviceID, VolumeName, @{n='SizeGB';e={[math]::Round($_.Size/1GB,1)}}, @{n='FreeGB';e={[math]::Round($_.FreeSpace/1GB,1)}}

  1.4. ПРОВЕРКА. Вы должны увидеть буквы дисков и столбец FreeGB.

  Как выбрать диск:
    - Нужно минимум 10 ГБ свободно, лучше 20+ ГБ.
    - Только локальный SSD. НЕ ставить на сетевые диски (Mega, rclone, ssh).
    - Не желательно на системный диск C (чтобы не засорять систему).

  Для вашей машины лучший выбор: диск D (SSD, 116 ГБ свободно).
  Если диск D по каким-то причинам не подходит, используйте G или E.

  ВНИМАНИЕ: если у вас команда df показывает Avail 0 и 100% везде — это
  баг порта утилиты df под Windows. Она не умеет читать свободное место
  на NTFS. Не верьте ей, верьте командам из пунктов 1.2 / 1.3.


--------------------------------------------------------------------------------
  ЧАСТЬ 2. УСТАНОВКА OLLAMA
--------------------------------------------------------------------------------

  2.1. Скачайте установщик с официального сайта:  ollama.com/download
       Файл называется OllamaSetup.exe

  2.2. Запустите установщик. Он поставится по умолчанию в системную папку.
       Сама программа весит немного, оставить её на диске C — нормально.
       (Модели мы вынесем отдельно, в ЧАСТИ 3.)

  2.3. Если хотите поставить и саму программу на диск D — откройте cmd
       в папке, куда скачали установщик, и запустите:

       OllamaSetup.exe /DIR=D:\Ollama

  2.4. После установки ОБЯЗАТЕЛЬНО закройте окно PowerShell и откройте новое.
       Это нужно, чтобы система подхватила новую команду ollama.

  2.5. ПРОВЕРКА. В новом окне PowerShell введите:

       ollama --version

  Ожидаемый результат: показывается номер версии, например "ollama version 0.x.x"

  Если пишет "ollama не является внутренней командой" — закройте PowerShell
  полностью, откройте заново и повторите. Если всё равно не видит — перезагрузите ПК.


--------------------------------------------------------------------------------
  ЧАСТЬ 3. ПЕРЕНОС ПАПКИ МОДЕЛЕЙ НА ДИСК D
--------------------------------------------------------------------------------

  По умолчанию модели сохраняются в C:\Users\user\.ollama\models
  Мы перенаправим их на диск D.

  3.1. Создайте папку вручную через проводник:  D:\OllamaModels
       (Ollama иногда не создаёт её сама, поэтому создаём заранее.)

  3.2. Задайте переменную окружения. В PowerShell введите одной строкой:

       [Environment]::SetEnvironmentVariable("OLLAMA_MODELS", "D:\OllamaModels", "User")

  3.3. Альтернативный способ (если команда выше не сработала):
       - Пуск -> наберите "переменные среды" -> "Изменение переменных среды текущего пользователя"
       - Нажмите "Создать"
       - Имя переменной:   OLLAMA_MODELS
       - Значение:         D:\OllamaModels
       - Нажмите ОК

  3.4. ВАЖНО: полностью закройте Ollama.
       Правый клик по иконке Ollama в трее (возле часов) -> Quit Ollama.
       Затем запустите Ollama заново из меню Пуск.

  3.5. ПРОВЕРКА №1. В новом окне PowerShell введите:

       $env:OLLAMA_MODELS

  Ожидаемый результат: путь D:\OllamaModels

  3.6. ПРОВЕРКА №2. Введите:

       ollama list

  Ожидаемый результат: пустая таблица (моделей ещё нет) — это нормально.
  Главное, чтобы команда отработала без ошибки.

  3.7. ПРОВЕРКА №3 (после загрузки модели в ЧАСТИ 5).
       Убедитесь, что папка D:\OllamaModels НЕ пустая — там появятся файлы моделей.
       Если файлы появились в C:\Users\user\.ollama\models — значит переменная
       не сработала, идите в пункт 9.2 аварийного сценария.


--------------------------------------------------------------------------------
  ЧАСТЬ 4. ТЕСТ СОВМЕСТИМОСТИ С ПРОЦЕССОРОМ  (САМЫЙ ВАЖНЫЙ ШАГ)
--------------------------------------------------------------------------------

  ПОЧЕМУ ЭТО ВАЖНО:
  У вашего процессора i7-3770 есть поддержка AVX, но НЕТ поддержки AVX2.
  Часть современных сборок программ рассчитана на AVX2 и падает с ошибкой
  "Illegal instruction" (недопустимая инструкция). Поэтому сначала проверяем
  на самой маленькой модели. Если она запустится — всё в порядке.

  4.1. Введите команду (модель крошечная, скачается быстро):

       ollama run llama3.2:1b "Сколько будет 2 плюс 2?"

  4.2. ПРОВЕРКА — возможны два исхода:

       ВАРИАНТ А (хороший):
         Модель ответила текстом (например "2 плюс 2 равно 4").
         -> Всё работает. Переходите к ЧАСТИ 5.

       ВАРИАНТ Б (плохой):
         Вылетела ошибка "Illegal instruction" или окно мгновенно закрылось,
         или ошибка вида "invalid opcode".
         -> Идите в пункт 9.1 (аварийный сценарий) и пробуйте по порядку.

  Выйти из интерактивного режима модели можно командой:  /bye


--------------------------------------------------------------------------------
  ЧАСТЬ 5. ЗАГРУЗКА РАБОЧЕЙ МОДЕЛИ
--------------------------------------------------------------------------------

  5.1. Скачайте модель для кода (весит ~2 ГБ, качается не быстро):

       ollama pull qwen2.5-coder:3b

  5.2. ПРОВЕРКА №1. После загрузки введите:

       ollama list

  Ожидаемый результат: в списке появилась строка qwen2.5-coder:3b

  5.3. ПРОВЕРКА №2. Запустите её с реальной задачей:

       ollama run qwen2.5-coder:3b "Напиши скрипт на PowerShell, который выводит список файлов больше 100 МБ"

  Ожидаемый результат: модель выдаёт осмысленный код.

  5.4. Почему именно 3B, а не 7B:
       - Модель 3B весит ~2 ГБ и целиком влезает в ваши 4 ГБ видеопамяти.
       - Модель 7B весит ~4.7 ГБ, не влезает, уходит частично на процессор,
         и скорость падает до 2-4 токенов в секунду. Это и есть "боль".
       - Если хочется ещё быстрее — есть облегчённая версия:

         ollama run qwen2.5-coder:1.5b

  Выйти из режима модели:  /bye


--------------------------------------------------------------------------------
  ЧАСТЬ 6. ПРОВЕРКА, ЧТО МОДЕЛЬ РАБОТАЕТ НА ВИДЕОКАРТЕ
--------------------------------------------------------------------------------

  6.1. Откройте ДВА окна PowerShell.

  6.2. В первом окне запустите генерацию с длинным запросом:

       ollama run qwen2.5-coder:3b "Напиши подробный скрипт резервного копирования папки с проверкой даты и логированием"

  6.3. Пока модель думает, во ВТОРОМ окне введите:

       ollama ps

  6.4. ПРОВЕРКА. Смотрим столбец PROCESSOR:

       "100% GPU"            -> отлично, работает полностью на видеокарте
       "частично CPU/GPU"    -> половина на процессоре, будет медленнее
       "100% CPU"            -> видеокарта не подхватилась, см. 9.3

  6.5. ДОПОЛНИТЕЛЬНАЯ ПРОВЕРКА. Во втором окне введите:

       nvidia-smi

  Смотрим строку Memory-Usage. Во время генерации занятая память должна
  подскочить примерно на 2 ГБ, а GPU-Util быть высоким (30-100%).


--------------------------------------------------------------------------------
  ЧАСТЬ 7. ТОНКАЯ НАСТРОЙКА ПОД 4 ГБ ВИДЕОПАМЯТИ
--------------------------------------------------------------------------------

  7.1. Ограничение размера контекста (чтобы модель не вылезала за память).
       Войдите в модель:

       ollama run qwen2.5-coder:3b

       Затем в режиме диалога введите:

       /set parameter num_ctx 4096

  7.2. Чтобы модель не выгружалась из памяти между запросами (быстрее отвечает).
       Выполните в PowerShell один раз:

       setx OLLAMA_KEEP_ALIVE 30m

       После этой команды нужно перезапустить Ollama (Quit в трее -> запуск заново).

  7.3. ПРОВЕРКА. После перезапуска снова запустите модель и проверьте
       через ollama ps, что она по-прежнему на GPU и отвечает быстро.


--------------------------------------------------------------------------------
  ЧАСТЬ 8. ТАБЛИЦА: ЧТО ПОТЯНЕТ ВАШЕ ЖЕЛЕЗО
--------------------------------------------------------------------------------

  Модель                  Размер    Влезет в 4 ГБ?   Скорость (примерно)
  ----------------------  --------  ----------------  --------------------
  qwen2.5-coder:1.5b      ~1.1 ГБ   да, полностью     ~40-60 токенов/сек
  qwen2.5-coder:3b        ~2.0 ГБ   да, полностью     ~20-30 токенов/сек
  llama3.2:3b             ~2.0 ГБ   да, полностью     ~20-30 токенов/сек
  gemma2:2b               ~1.6 ГБ   да, полностью     ~30-40 токенов/сек
  qwen2.5-coder:7b        ~4.7 ГБ   нет, частично CPU ~2-4 токенов/сек

  РЕКОМЕНДАЦИЯ: держите две модели — qwen2.5-coder:3b как основную и
  qwen2.5-coder:1.5b как быструю для мелких задач. Модель 7B не используйте.


--------------------------------------------------------------------------------
  ЧАСТЬ 9. АВАРИЙНЫЕ СЦЕНАРИИ
--------------------------------------------------------------------------------

  9.1. ОШИБКА "ILLEGAL INSTRUCTION" (из ЧАСТИ 4)
  --------------------------------------------------------------------------

  Пробуйте ПО ПОРЯДКУ. После каждого пункта повторяйте тест из 4.1.
  Как только заработало — останавливайтесь.

  Попытка 1. Обновите Ollama до последней версии (в новых версиях
             сделан динамический выбор ядра процессора):

             winget upgrade Ollama.Ollama

             Затем закройте Ollama в трее, запустите заново, повторите тест.

  Попытка 2. Используйте llama.cpp напрямую, со сборкой под AVX (без AVX2).
             - Откройте github.com/ggml-org/llama.cpp/releases
             - Скачайте архив с именем, содержащим "bin-win-avx-x64"
               (именно avx, НЕ avx2)
             - Распакуйте, запустите llama-server.exe и проверьте, что не падает

  Попытка 3. Установите LM Studio (lmstudio.ai).
             В настройках есть выбор среды выполнения (runtime) —
             можно явно указать AVX без AVX2. Графический интерфейс,
             удобен для старта.

  Попытка 4. Установите Docker Desktop и запустите образ ollama/ollama.
             Иногда помогает за счёт другой сборки.


  9.2. ПЕРЕМЕННАЯ OLLAMA_MODELS НЕ СРАБОТАЛА
  --------------------------------------------------------------------------

  Симптом: файлы моделей появляются в C:\Users\user\.ollama\models
  вместо D:\OllamaModels.

  Решение через симлинк (ссылка). Откройте cmd ОТ ИМЕНИ АДМИНИСТРАТОРА
  (правый клик по "Командная строка" -> Запуск от имени администратора)
  и выполните:

    mklink /D C:\Users\user\.ollama\models D:\OllamaModels

  ВНИМАНИЕ: перед этим убедитесь, что Ollama закрыта (Quit в трее).
  И что оригинальная папка C:\Users\user\.ollama\models удалена,
  если она существует и не пуста (перенесите её содержимое на D).


  9.3. МОДЕЛЬ СЧИТАЕТ НА ПРОЦЕССОРЕ, А НЕ НА ВИДЕОКАРТЕ
  --------------------------------------------------------------------------

  Симптом: ollama ps показывает 100% CPU или низкий GPU-Util в nvidia-smi.

  Что проверить по порядку:
    1. Драйвер видеокарты. Введите nvidia-smi — если не работает,
       обновите драйвер с сайта NVIDIA.
    2. Модель слишком большая для 4 ГБ. Возьмите 3B вместо 7B.
    3. Контекст слишком большой. Уменьшите: /set parameter num_ctx 4096
    4. Проверьте, не занята ли видеопамять другими программами
       (браузер с множеством вкладок может съедать память).


  9.4. ВСЁ РАБОТАЕТ, НО ОЧЕНЬ МЕДЛЕННО
  --------------------------------------------------------------------------

  - Возьмите модель 1.5b вместо 3b.
  - Уменьшите контекст до 2048.
  - Закройте тяжёлые программы (браузер, игры) во время работы модели.
  - Помните: DDR3-1333 медленная. Скорость в 20-30 токенов/сек — это
    нормальный потолок для вашего железа, больше не ждите.


--------------------------------------------------------------------------------
  ЧАСТЬ 10. ЧТО ДЕЛАТЬ, ЕСЛИ БЕСПЛАТНАЯ ОБЛАЧНАЯ МОДЕЛЬ ОТКЛЮЧИТСЯ
--------------------------------------------------------------------------------

  У вас есть несколько независимых путей. Если один закрывается —
  переключаетесь на другой, и работа продолжается с того же места.

  ПУТЬ 1. Локальная модель (то, что вы сейчас настраиваете).
          Плюсы: бесплатно всегда, без лимитов, приватно.
          Минусы: модель слабее, чем облачные.

  ПУТЬ 2. Бесплатные облачные API-ключи (подключаются как свой ключ).
          Варианты: Google Gemini, Groq, OpenRouter, Cerebras, NVIDIA NIM.
          Плюсы: модели сильнее, чем локальные.
          Минусы: суточные лимиты, которые сбрасываются каждый день.

  ПУТЬ 3. Бесплатная модель внутри OpenHands Cloud (DeepSeek V4 Flash).
          Плюсы: работает прямо сейчас без всякой настройки.
          Минусы: это акция, может закончиться в любой момент.

  КАК ПЕРЕКЛЮЧАТЬ МОДЕЛЬ ВНУТРИ ОДНОЙ БЕСЕДЫ В OPENHANDS:
    - В поле ввода есть кнопка выбора профиля модели.
    - Или используйте команду:   /model           (список профилей)
                                 /model <имя>     (переключить)
    - Переключение СОХРАНЯЕТ всю историю и контекст беседы.
    - Применяется к следующим шагам, прошлое не переписывается.

  ВАЖНО ПОНИМАТЬ ПРО "СГОРАНИЕ":
    - Токены не "сгорают". У вас нет купленного запаса токенов.
    - "Счётчик токенов" в интерфейсе — это заполнение контекста беседы,
      а не кошелёк. Он не тратится и не обнуляется со временем.
    - Когда акция кончится, бесплатная модель просто станет платной.
      Если баланс ноль — запросы к ней перестанут проходить с ошибкой.
    - Начатая разработка НЕ теряется: файлы лежат в проекте и в git,
      а беседа переключается на другую модель и продолжается.

  ПРАКТИЧЕСКИЙ СОВЕТ:
    Не прыгайте между моделями без нужды внутри одной задачи.
    Если сменили модель — коротко напомните, где вы находитесь:
    "продолжаем утилиту X, сделали шаг 2, теперь шаг 3".


--------------------------------------------------------------------------------
  ЧАСТЬ 11. ПОЛЕЗНЫЕ КОМАНДЫ ДЛЯ СПРАВКИ
--------------------------------------------------------------------------------

  Проверка версии Ollama:
      ollama --version

  Список скачанных моделей:
      ollama list

  Скачать модель:
      ollama pull <имя модели>

  Запустить модель с запросом:
      ollama run <имя модели> "ваш вопрос"

  Интерактивный режим модели (выйти — /bye):
      ollama run <имя модели>

  Что сейчас загружено и где считается (CPU/GPU):
      ollama ps

  Удалить модель:
      ollama rm <имя модели>

  Состояние видеокарты:
      nvidia-smi

  Где лежат модели (проверка переменной):
      $env:OLLAMA_MODELS

  Свободное место на дисках:
      Get-Volume | Where-Object {$_.DriveLetter} | Select-Object DriveLetter, @{n='FreeGB';e={[math]::Round($_.SizeRemaining/1GB,1)}}
